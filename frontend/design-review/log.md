# 디자인 점검 기록 (S15P21A605-29)

절차는 [../docs/conventions/design-review.md](../docs/conventions/design-review.md). 라운드를 아래에 덧붙인다.

## 라운드 1 — 2026-09-02 · 테마 토글

라운드 4 가 남긴 "수동 토글 없음" 을 채운다. 아이콘은 이미 있는 `lucide-react` 를 쓴다
(`leaderboard`·`stock-card`·`fee-event-banner` 가 이미 이 라이브러리를 쓰고 있어 계보가 하나다).

### 만든 것

- `src/lib/theme.ts` — 저장소 키·값 목록·`applyTheme`·`readTheme`. `system` 은 "저장된 선택
  없음" 이고, `<html>` 에서 클래스를 걷어 라운드 4 의 미디어 쿼리에 넘기는 상태다.
- `src/components/theme-toggle.tsx` — 시스템(`Monitor`) → 라이트(`Sun`) → 다크(`Moon`) 로
  도는 아이콘 버튼. 상단 바의 닉네임과 로그아웃 사이.
- `src/app/layout.tsx` — 첫 페인트 전에 저장값을 얹는 인라인 스크립트.

라운드 4 에서 스토리북 때문에 만들어 둔 `.light` / `.dark` 탈출구가 그대로 토글의 조작
지점이 됐다. 새로 만든 CSS 는 없다.

### 걸린 것 세 가지

1. **깜빡임.** OS 는 라이트인데 저장값이 다크면, 서버는 클래스 없이 그리고 `useEffect` 는
   페인트 뒤에 돌아 화면이 라이트로 한 번 그려졌다가 바뀐다. Next 문서
   (`node_modules/next/dist/docs/01-app/02-guides/preventing-flash-before-hydration.md`)
   가 이 경우를 다룬다 — `<head>` 의 인라인 스크립트가 HTML 파싱 중 동기로 돌아야 한다.
2. **개발 모드에서 그 스크립트가 지워진다.** 같은 문서에 있다. Strict Mode 재마운트가
   `<html>` 의 속성을 JSX 가 관리하는 값으로 되돌려 스크립트가 얹은 클래스를 날린다.
   `useLayoutEffect` 로 다시 얹는다 (프로덕션에서는 같은 값 재적용이라 무해).
   **학습 지식으로 짰으면 놓쳤을 부분이고, 개발 서버로 하는 이 점검 루프 자체가 깨졌을 것이다.**
3. **린트 두 건.** `set-state-in-effect` 와 `static-components`.
   앞은 `useSyncExternalStore`(서버 스냅샷 `null`)로 바꿔 풀었다 — `login-buttons.tsx` 가
   이미 쓰는 패턴이라 집안 방식을 따랐고, 하이드레이션 불일치도 같이 사라진다.
   뒤는 `ICONS[theme]` 로 컴포넌트를 골라 그리던 것을 `ThemeIcon` 분기 컴포넌트로 바꿨다.
   `NEXT_THEME` 표를 둬 인덱스 계산(`noUncheckedIndexedAccess` 걸림)도 없앴다.

### 결과

브라우저에서 실제로 눌러 확인 (OS 는 라이트로 고정):

| 단계   | `<html>` class | `--background` | 저장값   |
| ------ | -------------- | -------------- | -------- |
| 초기   | (없음)         | `#dfe3e9`      | `null`   |
| 클릭 1 | `light`        | `#dfe3e9`      | `light`  |
| 클릭 2 | `dark`         | `#0c0e11`      | `dark`   |
| 클릭 3 | (없음)         | `#dfe3e9`      | `system` |

- **깜빡임 없음**: 다크로 저장한 뒤 새로고침하면 `DOMContentLoaded` 시점에 이미 `.dark` 다
  (하이드레이션 전, HTML 파싱 중 적용). OS 가 라이트인데도 그렇다.
- 콘솔 경고·에러 없음 (하이드레이션 불일치도, `useLayoutEffect` 서버 경고도 없다).
- `aria-label` 이 현재 상태를 읽어 준다 ("테마 다크. 눌러서 바꿉니다").
- 상단 바는 데스크톱·모바일(390px) 모두 여전히 한 줄이다.

남은 것:

- **로그인 화면에는 토글이 없다.** 상단 바가 없는 화면이라(`/login` 은 레이아웃 그룹 밖)
  로그인 전에는 OS 설정만 따른다.
- 라운드 3·4 에서 넘어온 것: 홈이 비어 있다 · 브랜드 버튼 높이 차 · 모바일 표의 시각적
  스크롤 표시 · Google 버튼 다크 에셋.

`pnpm build` · `pnpm typecheck` 통과, `pnpm test` 15개 통과, `pnpm lint` `src` 무결,
`pnpm theme:check` 최신.

## 라운드 2 — 2026-09-02 · 성능 측정 자동화

화면마다 개발자 도구 네트워크 탭을 여는 대신 `pnpm perf` 로 표를 뽑는다
(`scripts/perf.mjs`). Playwright 는 이미 있어 새 의존성은 없다. 절차는
[../docs/conventions/design-review.md](../docs/conventions/design-review.md#성능).

찍는 화면 목록은 `scripts/routes.mjs` 로 `shots.mjs` 와 공유한다 — 두 벌로 갈라지면
한쪽에만 화면이 추가되는 사고가 난다.

### 발견

**Pretendard 폰트가 2.0MB 이고 모든 화면에 걸린다** (`src/fonts/PretendardVariable.woff2`).
첫 방문 전송량이 어느 화면이든 2.1MB 대이고, 그중 폰트가 아니었던 건 30kB 남짓이다.

처음 만든 표는 `/login` 만 2173kB 이고 나머지는 한 자리 kB 로 나왔다. **측정 쪽 결함이었다** —
브라우저 컨텍스트를 공유해 폰트가 첫 화면에서만 계산됐다. 화면마다 컨텍스트를 새로 파도록
고치니 전부 2.1MB 로 드러났다. 도구가 틀린 그림을 그리면 없느니만 못하다.

`display: "swap"` 이라 렌더를 막지는 않아 LCP 는 110~145ms 로 나쁘지 않다. 문제는 첫 방문의
다운로드 무게고, 모바일에서 특히 그렇다.

### 판단 보류

Pretendard 는 서브셋 판(상용 2,780자)을 배포하지만 완성형 11,172자에서 줄어든다.
이 앱은 **사용자가 임의의 닉네임과 문의 본문을 입력**하므로, 빠진 글자가 문장 중간에서
시스템 폰트로 떨어지는 위험이 있다. 무게와 글자 커버리지를 바꾸는 결정이라 여기서 고르지
않고 남긴다. 선택지는 셋이다.

1. 서브셋 폰트로 교체 — 가장 가볍고, 드문 글자가 깨질 수 있다.
2. `unicode-range` 로 상용/확장 두 벌 분할 — 흔한 글자만 먼저 받고 나머지는 필요할 때.
3. 그대로 둔다 — `swap` 이라 렌더는 안 막히고, 재방문은 캐시된다.

### 그 밖에

- 인증이 필요한 7개 화면이 500 이었다. 백엔드가 떠 있지 않아서고 프론트 결함이 아니다
  (표에 `!` 로 표시되고 "수치가 의미 없다" 고 알린다). 백엔드를 띄우고 다시 재야 한다.
- `next start` 가 `output: standalone` 설정에 대해 경고를 낸다. 측정에는 지장이 없었지만
  실제 배포는 `node .next/standalone/server.js` 를 쓴다.

`pnpm lint` `scripts` 무결.

## 라운드 7 — 2026-09-02 · 토큰 파이프라인 교착 수정

`pnpm theme:check` 가 실패해 커밋이 막혔다. 라운드 4 에서 내가 넣은 결함이다.

### 원인

생성기가 다크 변수를 두 곳에 낸다. 최상위 `.dark { }` 와, 라운드 4 에서 추가한 중첩
`@media (prefers-color-scheme: dark) { :root:not(.light) { } }` 다. 두 곳 모두 같은
`darkVars` 문자열을 쓰는데 들여쓰기가 2칸으로 박혀 있었다. 중첩된 쪽은 4칸이어야 한다.

그래서 이렇게 맞물렸다.

1. `pnpm theme` 가 2칸으로 쓴다.
2. `lint-staged` 의 prettier 가 4칸으로 고친다.
3. `theme:check` 가 파일과 생성물을 바이트로 비교해 "DESIGN.md 와 어긋났다" 며 막는다.
4. `pnpm theme` 를 다시 돌려도 2칸으로 돌아가 1번으로 간다.

둘 다 제 할 일을 하는데 영영 풀리지 않는다. 들여쓰기를 손으로 맞추는 건 같은 사고를
다음 중첩 블록에서 되풀이하므로, **생성기가 저장소의 prettier 설정을 거쳐 쓰도록** 했다
(`resolveConfig` + `format`). 이제 생성물이 정의상 prettier 와 일치한다.

### 결과

- `theme → format` 왕복: prettier 가 "unchanged".
- `format → theme:check` 왕복: 통과.
- prettier 가 `@custom-variant` / `@slot` 을 다시 포맷했으므로 테마가 실제로 도는지
  다시 확인했다 — 네 갈래 모두 통과하고, 로그인 패널이 라이트 `#14171A` · 다크 `#1D2126` 로
  바뀐다 (`dark:` 변형이 살아 있다는 뜻).
- `theme:check` · `format:check` · `lint` · `test`(15) · `typecheck` 전부 통과.

## 라운드 3 — 2026-09-03 · 셸·마켓 화면 (S15P21A605-39~42)

라우트에 연결되지 않던 마켓 컴포넌트 14개를 실제로 흐르는 Tick 위에 올렸다. 좌측 패널 +
상단 지표 바 셸, 홈(오늘의 시장), 마켓(종목 목록 · 종가 선 그래프 · 주문 티켓), 관리자
재생 제어. 캡처는 `pnpm shots` 대상에 `/market` · `/admin/replay` 를 추가했다.

### 토큰

- Flashback 시안의 무채색 램프로 프레임을 밝혔다 — `frame #F8F9FA`, `line #E2E5E9`, `hairline`
  신설. 등락색은 시안(`#E8434F`)이 흰 배경에서 3.9:1 로 AA 미달이라 기존 값을 유지했다.
- `sidebar-*` 다섯과 `chart-line`·`chart-grid` 를 추가했다 (사이드바·차트가 생겼으므로
  "구현 시 추가" 조건이 충족됐다). 차트 선은 잉크 하나다 — 색은 숫자에만.

### 걸린 것

1. **확정 규칙만으로는 화면이 한 Tick 늦다.** "다음 `tickSeq` 가 오면 이전 Tick 확정" 만
   두면 가격이 31~36초 뒤에 바뀌어 "다음 종가까지" 가 0 이 돼도 아무것도 안 움직인다.
   조각이 300ms 멈추면 확정하는 정착 타이머를 더했다 (`tick-store.ts` 상단 주석). 다음
   번호 도착은 여전히 확정 조건이고 늦은 같은 번호 조각은 중복으로 버려진다.
2. **무료 종료 절대 시각이 계약에 없다.** `phaseEndsAt` 은 폐장이라 "무료 종료까지" 를
   그릴 수 없어 목이 `feeFreeEndsAt` 을 먼저 낸다. `_common.md §7.3` 에 올려야 한다.
3. **shadcn CLI 가 `button.tsx` 를 덮어썼다.** `--overwrite` 로 새 컴포넌트를 받을 때 기존
   버튼 크기 스케일이 함께 바뀌었다. 되돌렸다. `sonner.tsx` 는 `next-themes` 를 끌어와
   우리 테마와 겹치므로 토큰만 쓰도록 고쳐 의존성을 뺐다.
4. **재생 제어 화면은 표준 사용자에겐 404 다.** 독립 모드의 고정 사용자 권한은 **목**
   프로세스의 `MOCK_STANDALONE_ROLE` 이 정한다 — dev 서버에 주면 아무 일도 없다.

### 결과

라이트·다크 · 1440px 에서 홈·마켓·재생 제어 셋 다 콘솔 오류 없이 렌더. 배속 30 에서
가격·Tick 번호·평가액·히트맵이 같은 순간에 바뀐다. `pnpm build` · `typecheck` · `lint` ·
`test` 44개 · `theme:check` 통과.

남은 것: 조기 종료 버튼(계약이 사라져 만들지 않았다) · 뉴스·채팅은 목이 아직 흘리지
않아 빈 상태만 보인다 · 모바일은 아이콘 열로 접히는 것까지만.

## 라운드 4 — 2026-09-04 · 시안 레이아웃으로 재구성

라운드 3 캡처를 실제 모니터(2000px)에서 보니 셋이 어긋났다. 본문이 `mx-auto` 로 가운데
몰려 패널 옆이 비었고, 마켓이 뷰포트를 쓰지 않아 차트 아래가 비었고, 여백이 시안보다 컸다.
제공된 Flashback 시안(레일 · 지표 헤더 카드 · 3열 · 하단 뉴스 띠)에 맞춰 다시 짰다.

### 고친 것

- `PAGE_CONTAINER` 에서 `mx-auto`·`max-w` 를 뺐다. 좌측 패널 옆 본문 열을 왼쪽부터 채운다.
- 셸: 회색 프레임 위 12px 격자 — 좁은 레일 카드(아이콘 + 라벨 타일) · 워드마크와 대문자
  라벨 지표(REPLAY DATE · TOTAL ASSETS · CASH · TODAY · RANK · USD/KRW)를 든 헤더 카드.
- 마켓: 종목 목록(분류 탭 · 전체/관심/ETF 칩 · 정렬 · 별) / 상세(면 그래프 · 3개월·1년·전체
  · 신호등 자리) + 가로 주문 패널(매수·매도 나란히) / 리더보드 + 라이브 채팅 / 하단 NEWS 띠.
  `lg` 이상에서 `100vh` 를 채우고 패널 안에서 스크롤한다.
- 리더보드 목록 스텁 `GET /api/v1/rankings` 을 목에 추가했다 (원장 한 줄).

### 걸린 것

1. **세로 flex 안에서 `h-[…]` 가 무시된다.** `flex-1` 의 basis 0 이 height 를 이겨 마켓
   래퍼가 내용 높이로 자랐고 차트가 1,200px 로 늘어났다. `flex-1` 을 빼고 높이만 줬다.
2. **grid 행은 기본이 내용 높이다.** `grid-rows-[minmax(0,1fr)]` 을 줘야 열이 컨테이너
   높이에 갇힌다.
3. **Base UI Select 는 값을 그대로 보인다.** `items` 를 root 에 넘겨야 라벨이 뜬다
   (정렬 셀렉트가 "DEFAULT" 로 보였다).
4. **원장을 고치면 dev 서버 재시작.** rewrite 가 기동 시 고정이라 리더보드가 404 였다.

### 결과

2000×1130 에서 홈·마켓·마이페이지가 왼쪽 축을 공유하고 마켓은 문서 높이 = 뷰포트 높이.
스토리 9종 추가(목록·등락·차트·채팅·뉴스 띠·레일·로고·phase 배지·리더보드), 헤더 스토리는
스토어를 심어 지표가 보인다. `pnpm build-storybook` 통과, 단위 44개 통과.
