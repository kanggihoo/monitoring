# ADR-0003: 테스트 지원 기능을 프로파일이 아닌 fail-closed 플래그로 격리

- 상태: 승인
- 결정일: 2026-08-28
- 관련: [ADR-0001](0001-session-based-authentication.md), [ADR-0002](0002-web-cookie-app-header-transport.md), [`../../../docs/specs/test-support.md`](../../../docs/specs/test-support.md)

## 문맥

- IdP 미경유 User 세션 발급 경로 필요: 개발자 전원 `ADMIN`이라 USER 시점 확인 불가, 인증 필요 API 부하 테스트 불가.
- OAuth 우회 경로: 프로덕션 노출 시 임의 세션 발급 위험.
- Spring 프로파일 부재 (`application-*.yml` 없음): 프로파일 격리 도입 시 불필요한 체계 신설 비용 발생.
- 기존 시큐리티 원칙: 공개 경로 개별 명시(와일드카드 개방 금지), 전역 CSRF 검사 예외는 앱 인증 헤더 요청뿐.

## 결정

1. **단일 게이팅 프로퍼티**: `app.test-support.enabled` (기본값 `false`, 미설정 시 fail-closed). `@ConditionalOnProperty`로 빈 생성 자체를 차단.
2. **`!prod` 프로파일 미사용**: fail-open 위험(프로파일 누락 배포 시 자동 활성화) 방지.
3. **단일 스위치**: 테스트 로그인·샌드박스·시딩을 동일 위험도로 묶어 단일 제어, 분기 최소화.
4. **기동 시 API 키 검증**: 활성화 상태에서 키 미입력 또는 32자 미만 시 기동 실패. 키 비교는 상수 시간(Constant-time).
5. **기존 시큐리티 설정 불변**: `@ConditionalOnProperty` 기반 전용 필터 체인 격리, CSRF 예외는 전용 체인 내부로 한정.
6. **관리자 경로 샌드박스**: 전용 체인 미매칭으로 기존 관리자 인가 검사 유지. 컨트롤러 빈만 플래그로 비활성화.
7. **`test_users` 전용 테이블**: `users` 컬럼 추가 없이 `test_users` 행 존재 여부로 Test User 식별.
8. **샌드박스 진입 감사 로그 미기록**: 대상이 본인 배정 Test User 1명으로 한정되어 사칭 불가, 진입 시 권한 축소(ADMIN -> USER), 분쟁/대조 가치 없음. (실사용자 대상인 권한 변경·강제 세션 종료만 `admin_audit_logs` 기록).

## 대안 비교

- **`!prod` 프로파일**: 기각. fail-open 취약점(미지정 배포 시 노출) 및 체계 구축 비용.
- **다중 스위치 분리 (`enabled` + `seed`)**: 기각. 관리자 콘솔 오염 방지 목적이었으나 설정/환경 분기 증가. 조회 쿼리 제외 조건 1줄로 해결.
- **`users` 테이블 컬럼 추가**: 기각. 프로덕션 스키마 영구 오염 및 제거 시 DDL 마이그레이션 필요.
- **인증 주체 OIDC 상속 제거**: 기각. 더미 ID 토큰 제거 가능하나 기존 인증 경로 영향 대비 실익 없음(클레임 조회 코드 부재).
- **부하 테스트 세션 런타임 생성**: 보류. 사전 시딩 명시 요구 및 부하 측정 중 생성 오버헤드 배제 필요.

## 핵심 근거

- **인증 우회 기본값 fail-closed**: 프로파일(미지정 시 켜짐) vs 프로퍼티(미지정 시 꺼짐).
- **빈 미생성이 경로 차단보다 안전**: 인가 설정 오류 위험 원천 차단.
- **보안 설정 격리**: 비활성화 환경에서 보안 설정 내 테스트 흔적 전무.
- **불량 키 기동 실패**: 런타임 취약점 사전 차단.

## 영향

- **감수하는 것**
  - 플래그 활성화 환경에서 API 키 보유자의 세션 발급 가능. 피해는 `test_users` 범위로 제한.
  - 인증 주체에 더미 ID 토큰 포함: 클레임 신뢰 조회 코드 추가 금지(타입 문서화로 방지).
  - USER 시점 전환 사후 추적 불가 (명세 요구 9 미반영, 사칭 불가 구조 기반. 향후 대상 지정 인자 추가 시 재검토 필요).
  - `UserRepository` 직접 참조: 테스트 지원 서비스에서 신원 없는 User 생성 시 저장소 직접 호출 (의도적 Service 우회, 기능 제거 시 함께 제거).
  - 관리자 검색의 `test_users` 참조: 기능 제거 시 `DROP TABLE`과 함께 검색 제외 조건 삭제 필요 (유일한 격리 누출점).
  - 샌드박스 비활성화 404 응답: 전역 예외 처리기가 핸들러 부재를 500이 아닌 404로 명시 반환 필수.
  - 비활성화 경로 접근 시 403 반환: 시큐리티/CSRF 필터가 핸들러 매핑보다 선행 실행 (세션 미발급으로 노출 위험 없음).
  - 샌드박스의 Test User 자동 생성으로 "프로덕션 대상 부재" 보호 무효화: 잠금은 플래그가 전담.
- **가능해지는 것**
  - 관리자 재로그인 없는 USER 시점 전환.
  - 인증 필요 API 대상 부하 측정.
  - 간결한 기능 제거 (패키지 + 테이블 + 검색 제외 조건 삭제).

## 후속 결정

- 부하 테스트 시나리오 위치 및 실행 방식 ([`../decisions-later.md`](../decisions-later.md)).
- E2E/브라우저 테스트 인증 셋업 대체 여부.
- 시드 인원 확대 시 관리자 검색 외 추가 조치 필요 여부.
