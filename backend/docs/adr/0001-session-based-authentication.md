# ADR-0001: 세션 기반 인증 채택

- 상태: 승인
- 결정일: 2026-08-26

## 문맥
- 클라이언트: Next.js 웹 + Expo 앱
- 도메인: 모의투자 (실자금 없음. KYC·재인증·감사로그 불필요)
- 백엔드: 단일 Spring 인스턴스

## 결정
1. **자격증명**: 불투명 세션 ID. JWT 발급 안 함.
2. **저장소**: Redis. 인덱스 리포지터리를 쓴다 (`spring.session.data.redis.repository-type=indexed`).
3. **만료**: 유휴 1일(`${SESSION_TIMEOUT:1d}`). 절대 만료 없음.
4. **페이로드**: 인증 주체(`SecurityContext`)만 보관. 잔고·보유 종목 등 **도메인 데이터 저장 금지**.
   `role`은 authorities로 담되, 변경 시 `findByPrincipalName`으로 해당 User의 세션을 무효화한다.

## 대안 비교
- **JWT (AT+RT)**: 기각. 무상태 이점 없음(단일 백엔드). 즉시 무효화 불가, RT 저장소·갱신 큐잉 복잡도만 증가.
- **인메모리 세션**: 기각. 서버 재기동/스케일아웃 시 세션 소실. 헤더 운반 불가로 앱 연동 차단.

## 핵심 근거
- 무상태 필요 없는 환경. 세션의 즉시 무효화가 핵심.
- AT 단축은 결국 RT 서버 저장 유발. 복잡도 높은 유사 세션 재구현에 불과.
- 모의투자는 탈취 피해 작음. 절대 만료로 UX 해칠 이유 없음.
- `role`을 세션에서 빼면 매 인증 요청마다 DB 조회 + 커스텀 필터가 붙는다. 세션에 담고 변경 시 무효화하면 평상시 비용 0, 지연 0.

## 영향
- Redis 장애 시 전원 로그아웃.
- `findByPrincipalName`으로 사용자별 즉시 세션 만료 가능.
