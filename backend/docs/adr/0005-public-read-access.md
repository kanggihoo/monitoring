# ADR-0005: 미인증 열람을 개방한다

- 상태: 승인
- 결정일: 2026-09-09
- 관련: [ADR-0001](0001-session-based-authentication.md), [ADR-0004](0004-stomp-realtime-transport.md), [`public-market-access.md`](../../../docs/specs/public-market-access.md)

## 문맥

지금까지 이 서비스는 로그인을 거의 모든 것의 전제로 삼았다. 공개 엔드포인트는 둘뿐이고(`GET /api/v1/seasons/current`, 계약상 `GET /api/v1/chat/messages`), `/ws` 핸드셰이크도 `.anyRequest().authenticated()`에 걸린다.

그 경계는 우연이 아니라 **세 곳에서 각각 명시적으로 결정된 것**이다.

- [`mkt.md`](../../../docs/projects/market-replay-api/mkt.md) — "조회를 미인증에 개방하지 않는다". 근거는 미래 차단 원칙, 기획서 3.1.1이 로그인 전에는 "시즌 소개"만 두었다는 것, 12.1.5의 미인증 읽기가 채팅 한정이라는 것
- [ADR-0004](0004-stomp-realtime-transport.md) 결정 5 — "미인증 연결을 허용하지 않는다". 기각 근거는 "`/topic/tick`이 시세를 나르므로 **REST 시세 인증 우회 경로**가 된다"
- [`ws.md`](../../../docs/projects/market-replay-api/ws.md) 열린 질문 1 — 같은 결론으로 닫혀 있다

**제품 방향이 바뀌었다.** 가입하지 않은 사람이 시세와 콘텐츠를 먼저 보고 판단할 수 있어야 한다는 것이 새 전제다. 위 결정들은 그 전제 위에서 다시 판단해야 한다.

## 결정

1. **접근 판정은 현재 로그인 상태 하나로 한다.** 가입 이력으로 판단하지 않는다 — 등록된 User도 로그아웃 상태에서는 미인증이며 공개 열람만 가능하다 (용어는 [`../CONTEXT.md`](../CONTEXT.md)의 `Unauthenticated`).
2. **공개는 기능 단위로 개별 지정한다.** GET 전체를 열지 않는다. 표기는 [`_common.md`](../../../docs/projects/market-replay-api/_common.md) §2의 기존 3분류(`공개`/`사용자`/`관리자`)를 그대로 쓴다.
3. **`/ws` 핸드셰이크를 공개한다.** 이것은 **ADR-0004 결정 5를 뒤집는 것이다.**
4. **공개 토픽과 개인 큐의 구독 권한을 분리한다.** 미인증의 `/user/queue/me` 구독을 서버가 거부한다. 프론트도 미인증 상태에서는 그 destination을 구독하지 않는다 — 서버 거부는 방어선이지 정상 경로가 아니다.
5. **공개 토픽에 그 메시지의 목적이 아닌 개인 정보를 싣지 않는다.** `ranking.awarded`가 `/topic/event`로 타인의 닉네임·아바타·수익률을 브로드캐스트하므로, 신호만 보내고 상세는 REST 재조회로 바꾼다. `ranking.top10Changed`가 이미 쓰는 패턴이다.
   **`chat.message`는 예외로 그대로 둔다.** `/topic/chat`으로 `nickname`·`avatarId`·`content`를 싣지만, 채팅은 발화자가 누구인지가 곧 기능이라 익명화하면 기능이 사라진다. 가르는 기준은 "그 정보가 그 메시지의 목적인가"다 — 시상 알림의 목적은 "순위가 바뀌었다"이지 "누가 받았다"가 아니다.
6. **미래 차단 원칙은 그대로 지킨다.** 별도 조치가 필요 없다 — 절단은 인증이 아니라 조회 계층(`MarketPriceService.snapshotAsOf`)의 책임이고 REST와 WS가 같은 메서드를 쓴다.
7. **인증 상태가 바뀌면 WS 연결을 새로 맺는다.** 로그인·로그아웃 양방향 모두. STOMP의 Principal은 핸드셰이크에서 한 번 정해지므로 기존 연결에 구독만 추가할 수 없다 (ADR-0004 결정 4의 직접적 귀결).
8. **이번에 실제로 여는 것은 Tick 시세·뉴스 조회·게임 시계다.** 전체 랭킹은 계약상 공개로 열되 계좌 생성이 붙기 전까지 빈 값이 나간다. 채팅 조회는 `S15P21A605-85`로 이미 구현·공개되어 있어 새로 열 것이 없고, 미인증 WS가 열리면 `/topic/chat` 구독이 그대로 동작한다. 전송은 `사용자` 권한을 유지한다.

## 검토한 대안들

### GET 전체를 공개한다

기각. 개인 자산·주문내역·복기도 GET이다. 메서드는 공개 여부의 기준이 될 수 없다.

### REST만 열고 미인증 WS는 계속 막는다

기각. 초기 조회만 되고 갱신이 오지 않아, 방문자에게는 **멈춘 화면**이 보인다. 시세 서비스에서 그것은 열지 않은 것과 같다.

### 미인증 방문자에게도 세션을 발급한다

기각. 세션 저장소 부담이 늘고, 얻는 것이 없다. Principal이 없다는 사실 자체가 개인 큐 접근을 막는 가장 단순한 근거다.

## 핵심 근거

- **ADR-0004의 기각 근거는 독립적인 것이 아니라 파생된 것이었다.** "REST 시세 인증 우회 경로가 된다"는 `mkt.md`가 REST를 닫았다는 사실에 의존한다. REST를 함께 열면 우회할 대상이 없어져 근거가 자동으로 소멸한다.
- **미래 차단은 인증이 지키던 것이 아니다.** 공개 기준은 `replay_state.lastPublishedTickSeq` 하나이고, REST와 WS가 `snapshotAsOf`라는 같은 메서드로 절단한다. DB에 미래 데이터가 전부 적재돼 있어도 누가 부르든 발행된 틱까지만 나간다.
- **공개 토픽의 PII 문제에는 이미 리포 안에 해법이 있다.** 리더보드 전체 목록을 WS로 밀지 않고 REST 재조회로 돌린 결정이 그것이다. `ranking.awarded`만 그 패턴에서 벗어나 있었다.

## 기존 결정과의 관계

이 ADR은 인증 경계를 옮기므로 기존 결정 다섯 건을 전부 대조했다.

| 결정 | 관계 |
|---|---|
| [ADR-0001](0001-session-based-authentication.md) 결정 4 — 세션 페이로드는 인증 주체만, 도메인 데이터 저장 금지 | **보강.** 로그인 복귀 주소를 서버 세션에 넣지 않고 프론트가 갖기로 한 근거가 이것이다. 세션에 넣었다면 이 규약을 어겼을 것이다 |
| [ADR-0001](0001-session-based-authentication.md) 결정 3 — 유휴 1일, 절대 만료 없음 | **변경 없음.** 절대 만료는 이 작업 범위 밖이다 |
| [ADR-0002](0002-web-cookie-app-header-transport.md) — 웹 쿠키 / 앱 헤더 운반 | **변경 없음.** 미인증 핸드셰이크는 쿠키도 헤더도 없는 세 번째 경우일 뿐이라 리졸버에 새 코드가 없다. "1 유저 n 세션 독립 동작"은 "다른 브라우저·기기의 세션은 영향받지 않는다"는 이 작업의 수용 기준과 그대로 맞는다 |
| [ADR-0003](0003-test-support-isolation.md) — 테스트 지원 격리 | **변경 없음.** 전용 필터 체인은 별개다. 오히려 그 문맥이 적은 "공개 경로 개별 명시, 와일드카드 개방 금지" 원칙을 이 ADR이 그대로 계승한다 |
| [ADR-0004](0004-stomp-realtime-transport.md) 결정 4 — 핸드셰이크에서 인증, 인증용 인터셉터 없음 | **일부 개정.** `/ws`를 공개 경로에 넣기 위해 `SecurityConfig`를 수정한다. 나머지는 유지된다 — 미인증 구독 거부는 인증이 아니라 **인가**이며 결정 7의 구독 검증 인터셉터에 붙는다. **이 결정이 유지되기 때문에** 결정 7(인증 상태 변경 시 재연결)이 필요해진다 |
| [ADR-0004](0004-stomp-realtime-transport.md) 결정 5 — 미인증 연결 금지 | **폐기.** 이 ADR 결정 3이 대체한다 |
| [frontend ADR-0001](../../../frontend/docs/adr/0001-optimistic-route-guard.md) 결정 1 — `proxy.ts`는 세션 쿠키 유무만 확인 | **보완.** 쿠키 유무에 더해 경로가 공개인지 보호인지를 함께 본다. 백엔드 호출 금지는 그대로다 |
| [frontend ADR-0001](../../../frontend/docs/adr/0001-optimistic-route-guard.md) 영향 — "만료 쿠키 보유 시 로그인 이동 (의도된 동작)" | **뒤집힌다.** 공개 경로에서는 로그인으로 보내지 않고 미인증으로 그 화면을 유지한다. 보호 경로에서는 종전대로다 |

3층 방어 구조(라우트 힌트 / 데이터 계층 검증 / 위조 방지 토큰) 자체는 바뀌지 않는다. 1층의 입력이 하나 늘고 만료 시 착지점이 갈릴 뿐이라, 프론트에 새 ADR을 쓰지 않고 기존 ADR에 개정 이력을 남긴다.

## 영향

- **ADR-0004 결정 5가 무효가 된다.** 그 결정을 고정하던 테스트(`RealtimeTransportApiTest`의 미인증 핸드셰이크 401 검증)도 함께 뒤집힌다.
- **미인증 방문자가 닉네임을 읽게 된다.** 전체 랭킹과 채팅에 닉네임·아바타가 실려 나간다. 의도한 동작이며 가입 화면 고지를 두지 않기로 했다 — 닉네임은 사용자가 정한 표시명이고 랭킹·채팅 노출은 서비스의 명시적 기능이다. 탈퇴자 익명화(`withdrawn`)는 인증과 무관하게 유지된다. `soc.md`의 열린 질문으로 남아 있던 것을 이 ADR이 닫는다.
- 익명 연결 수·구독 수·호출 빈도에 상한이 없다. 애플리케이션에 제한을 신설하지 않기로 했으므로 [`../decisions-later.md`](../decisions-later.md)에 기록한다.
- 전체 랭킹은 계좌를 만드는 코드가 붙기 전까지 빈 값이다. 공개 열람의 수용 기준 중 랭킹 항목은 그 작업 이후에야 검증할 수 있다.
- [ADR-0001](0001-session-based-authentication.md)이 적은 "Redis 장애 시 전원 로그아웃"의 성격이 바뀐다. 전원이 미인증으로 떨어지되 **공개 열람은 계속된다** — 서비스가 통째로 멈추지 않는다.
- 로그인 복귀 주소를 백엔드가 받지 않으므로 오픈 리다이렉트 표면이 생기지 않는다. 복귀는 프론트가 자기 안에서 처리한다.
