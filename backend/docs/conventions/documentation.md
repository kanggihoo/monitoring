# 문서 작성 규칙

> 문서화 역할/경계/트리거 기준. 작성 템플릿은 `docs/templates/` 참조.

## 핵심 원칙

1. **단일 진실 원천**: 한 종류의 정보는 한 곳에만 둔다.
2. **지연 생성**: 빈 파일은 만들지 않는다 (필요 시점에 생성).
3. **역할 분리**: 문서는 Why, 코드는 What.

---

## 문서별 역할 및 경계

### 1. `architecture/`
- **역할**: 정적 구조 (패키지, 계층, 도메인 경계, 컴포넌트 책임).
- **경계**: 동적 흐름 ❌ (`flows/`), 설계 이유 ❌ (`adr/`), DB 구조 ❌ (`ERD.md`), 실행법 ❌ (`usage.md`).
- **갱신**: 새 도메인/패키지 추가, 계층 규칙 변경 시 갱신 (`overview.md` 하나로 시작).

### 2. `adr/` (Architecture Decision Records)
- **역할**: 되돌리기 어려운 아키텍처 결정 맥락 기록 (`제안 → 승인 → 대체/폐기`).
- **작성 기준 (3-AND 필수)**:
  1. 되돌리기 비용이 크다 (교체 시 한 분기 이상 소요)
  2. 맥락 없이는 이유를 알기 어렵다
  3. 실질적인 트레이드오프가 존재한다
- **규칙**: 삭제 금지 (새 ADR로 대체 후 상호 링크), 파일명 `NNNN-kebab-case.md`.

### 3. `flows/`
- **역할**: 기능 플로우 (시퀀스 다이어그램 + 단계별 설명).
- **경계**: 결정 이유 ❌ (`adr/`), 도메인 용어 정의 ❌ (`CONTEXT.md`).

### 4. `specs/` — 리포 루트 [`docs/specs/`](../../../docs/specs/)
- **위치**: **컨텍스트와 무관하게 리포 루트 한 곳**에 모은다. 명세는 코드가 아니라 기능 단위이며, 백엔드 단독으로 시작한 기능도 화면이 붙으면서 두 컨텍스트에 걸치게 된다. 작성 시점에 판정하지 않는다.
- **역할**: 착수 전 기능 명세 (문제/해결/사용자 스토리/구현·테스트 결정/범위 밖). 이슈 트래커로 올릴 원본.
- **경계**: 결정의 **근거** ❌ (`adr/`), 시퀀스 ❌ (`flows/`), 용어 정의 ❌ (`CONTEXT.md`). 파일 경로·코드 조각은 넣지 않는다 (금방 낡는다).
- **생명주기**: 구현 완료 후에도 남긴다. 결정이 바뀌면 spec이 아니라 ADR·컨벤션을 고치고, spec은 그 시점의 기록으로 둔다.

### 5. `CONTEXT.md`
- **역할**: 프로젝트 고유 도메인 용어집 (개념별 단어 확정 및 `_Avoid_` 명시).
- **경계**: 구현 디테일/결정 이유 ❌, 일반 프로그래밍 용어(타임아웃 등) ❌. 정의는 1~2문장 이내.

### 6. `decisions-later.md`
- **역할**: 미결정 사항 (백로그, 보류/조율 안건).
- **규칙**: 결정 완료 시 즉시 ADR 승격 또는 삭제 (완료 항목을 남기지 않음).

### 7. `usage.md`
- **역할**: 로컬 실행, 운영 절차, 트러블슈팅 가이드 (사람이 읽는 문서).
- **경계**: 구조 설명 ❌ (`architecture/`), 환경변수 상세 ❌ (`.env.example` 주석).

### 8. `conventions/`
- **`code.md`**: Java/Spring 코드 스타일, JPA/DTO 설계, 인증, 테스트 규칙.
- **`api.md`**: 엔드포인트 경로 규칙, HTTP 상태 코드 기준, 에러 포맷 (명세는 Swagger가 단일 진실).
- **`environment.md`**: 환경변수(`.env` vs `application.yml`) 배치 기준.
- **`docs/conventions/git.md`** (루트 공통): 브랜치/커밋 컨벤션.

### 9. `ERD.md`
- **역할**: DB 스키마 시각화 (Mermaid `erDiagram` + 텍스트 표 제약 설명).
- **경계**: 엔티티 클래스가 단일 진실. 스키마 변경 시 코드 수정 후 동기화.

### 10. 인라인 주석
- 코드 자체가 설명하는 What ❌, 설계 의도/배경인 Why ⭕ (`// ADR-NNNN 참조`).
