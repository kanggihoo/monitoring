# Decisions Later — 미결정 사항 (ai)

## 🕐 고도화 백로그 (나중에 할 것)

방향은 합의됐고 시점만 미룬 것. MVP 범위 밖.

| 항목 | 배경 | 우선순위 | 관련 |
| --- | --- | --- | --- |
| 요청 상관관계 ID 전파 | 백엔드 로그와 AI 로그가 지금은 따로 남는다. 백엔드가 붙인 `X-Request-Id`를 받아 로그에 실으면 한 요청을 양쪽에서 이어 볼 수 있다. 첫 도메인 기능이 붙어 실제로 추적이 필요해질 때 한다 | P2 | — |
| 모델 호출 계측 (토큰 사용량·지연) | 비용과 지연을 나중에 근거로 얘기하려면 호출 시점에 기록해둬야 한다. GMS 응답의 `usage` 를 로그에 남기는 것부터 시작하면 된다 | P2 | `app/services/llm.py` |
| 내부 인증 격상 | 공유 시크릿 하나는 키가 새면 그대로 열린다. 배포 형태가 정해지면 네트워크 격리(내부 네트워크에서만 노출)나 mTLS 로 올릴 수 있다 | P3 | 아래 "배포·기동 방식" |
| 모델 응답 캐시 | 같은 입력에 같은 답을 다시 만들면 비용만 든다. 백엔드 Redis 를 공유할지 별도로 둘지 포함해서 판단해야 한다 | P3 | — |
| 같은 조건에서의 헤드라인 변주 | 블록은 계정 시드로 후보 3개 중 하나를 골라 옆자리와 갈렸다. LLM 은 같은 조건이면 비슷한 문장으로 수렴하고, gpt-5 계열은 `temperature` 를 받지 않아 온도로 흩을 수도 없다. 계정 해시로 어조·시작 어휘 힌트를 프롬프트에 섞는 방향이 있다 | P2 | `prompts/daily-headline.md` |

## ⚠️ 보류/조율 (지금 갈등이거나 미정인 것)

방향이 안 정해진 것. 해결되면 ADR 로 승격한다.

| 항목 | 쟁점 | 옵션 | 상태 |
| --- | --- | --- | --- |
| 배포·기동 방식 | 백엔드 compose 에 서비스로 합칠지, 별도 컨테이너로 둘지, 단일 호스트에서 uvicorn 만 띄울지 미정. 내부 인증 방식과 묶여 있다 | A: 백엔드 compose 에 합침 / B: 별도 컨테이너 + 내부 네트워크 / C: 호스트에서 직접 실행 | 미정 |
| `/docs`·`/openapi.json` 공개 범위 | 내부 서비스라 문서를 열어둬도 위험이 낮지만, 배포 환경에서 외부로 노출되면 엔드포인트 목록이 그대로 드러난다. 현재는 모든 환경에서 열려 있다 | A: 모든 환경 공개 / B: local 만 공개 / C: 내부 호출 키로 보호 | 미정 |
| 프론트엔드 직접 호출 여부 | 현재는 **Spring 백엔드만 호출한다**고 가정해 `AI_CORS_ALLOW_ORIGINS` 를 비워뒀고(미들웨어 미부착) 사용자 JWT 도 검증하지 않는다. 프론트가 직접 부르게 되면 origin 을 채우는 것만으로는 부족하고 인증 구조 자체가 바뀐다 | A: 백엔드 경유 유지 / B: 프론트 직접 호출 허용 (CORS origin + JWT 검증 추가) | 미정 |
| 모델 가중치 수신 경로 | 가중치는 저장소에 커밋하지 않기로 했고(`.gitignore` 가 막는다) `AI_MODEL_DIR` 로 로컬 경로를 받게 해뒀다. 팀원·배포 환경이 그 파일을 **어디서 받아오는지**는 미정이다 | A: S3 / B: HuggingFace Hub / C: 로컬 수동 배치 유지 | 미정 |
