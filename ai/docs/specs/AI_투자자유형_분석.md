# 투자자 성향 분석 — 명세

> 온보딩 선언과 3일간의 거래 행동을 **같은 5단계 척도**로 옮기고, 그 둘을 대조해 결과지를
> 만든다. 이 문서 하나가 축·알고리즘·계약·테스트의 정본이다.
>
> 예외 둘 — 필드 타입·기본값은 `app/schemas/inbound.py`, 문안 실물은 `data/blocks/*.json`.
>
> **v2 (2026-09-17)** — 4축 8유형에서 5문항 5단계로 바꿨다. 옛 설계를 찾고 있다면 git
> 로그에 있다 (`docs/specs/AI_투자자유형_분석.md` 의 v1).

---

## 0. 이 기능이 하는 일

> "나는 이런 투자자라고 생각했는데, 실제로는 어떤 사람이었을까?"

시즌 시작 전 사용자가 자기 성향을 선언하고, 3일 뒤 거래로 판정한 성향과 대조한다.
**이 대조가 콘텐츠의 전부다.**

발표에서 나올 세 질문의 답이 설계 안에 있다.

| 질문 | 답 |
| --- | --- |
| 왜 이렇게 나눴나 | 5단계는 증권사 투자성향 분류를 그대로 쓴다. 매핑 규칙은 코드로 보여준다 |
| 3일만 보고 어떻게 아나 | "영구적 성격"이 아니라 "이번 시즌 관찰 행동"이라고 처음부터 명시한다 |
| AI 가 마음대로 정하나 | 판정은 100% 규칙 기반. LLM 은 설명만 한다 |

**세 번째는 실측으로 뒤집은 결정이다.** 판정을 LLM 에 맡겨 붙여 봤더니 경계 계좌 5회
재실행에서 한 축이 `[67, 49, 60, 67, 70]` 로 50 을 넘나들며 유형이 세 가지로 갈렸고,
존재하지 않는 코드를 두 번 생성했다.

## 1. 5단계

```
5~7   안정형       철벽의 자산 방어자
8~10  안정추구형    돌다리 두드리는 분석가
11~13 위험중립형    유연한 자산 조율사
14~16 적극투자형    변동성을 즐기는 트레이더
17~20 공격투자형    한 방을 노리는 승부사
```

**선언 쪽과 관찰 쪽이 같은 표를 쓴다.** 그래야 두 결과를 나란히 놓고 비교할 수 있다.

**유형 이름과 페르소나는 서비스가 붙인 것이다.** 학술적으로 검증된 것은 개별 지표의 계산식
이지 이름이 아니다 — README 와 발표 자료에 이 구분을 명시한다.

**수익률·승률·순위는 어느 항목에도 넣지 않는다.** 수익률은 결과이고 성향은 행동이다.

## 2. 온보딩 — 상황형 5문항

축 이름으로 묻지 않는다. `위험 감수 [높음]` 처럼 결과지와 같은 용어로 물으면 사용자가
정답을 아는 상태로 멋있어 보이는 쪽을 찍고, 그러면 대조가 무의미해진다.

```
Q1 투입 비중   시드머니 중 현금을 얼마나 남겨 둘 생각인가
Q2 손실 감내   계좌가 어디까지 빠져도 견딜 수 있나
Q3 진입 타이밍 어떤 자리에서 사는 편인가
Q4 급락 대응   보유 종목이 크게 빠졌을 때는
Q5 손실 정리   손실이 나고 있는 종목은
```

각 4지선다이고 답이 곧 1~4점이다. **다섯 문항이 전부 "위험을 얼마나 지는가" 한 축을
잰다** — 합산해서 한 점수로 만들기 때문이다.

**채점은 프론트가 그 자리에서 한다.** 합산과 구간 조회뿐이라 서버 왕복을 걸 이유가 없다.
서버는 `answers` 합이 보내온 점수와 맞는지만 검증한다.

**합산이 아니라 답 원본(`"24312"`)을 저장한다.** 구간 경계는 플레이테스트 뒤에 조정할 값
이라, 원본이 있어야 표를 고친 뒤 과거 선언을 다시 계산할 수 있다.

### 한 줄 입력 (선택 경로)

`POST /api/ai/onboarding/interpret` 이 자연어 한 문장을 5문항 답으로 옮긴다.
**이 기능에서 LLM 이 없으면 사라지는 유일한 자리다.**

출력이 숫자 다섯과 등급뿐이라 **입력이 지시를 덮어쓰려 해도 피해 범위가 지침이 아니라
구조로 막힌다.** 모델의 자기평가만 믿지 않는다 — 다섯이 전부 가운데 값이면 코드가 `LOW` 로
내리고, 프론트가 버튼 경로로 되돌린다.

사용자가 화면에서 기다리는 경로라 리포트용 클라이언트를 그대로 쓰지 않는다. 타임아웃 4초,
재시도 없음, 동시 실행 자리를 1.5초 안에 못 받으면 즉시 버튼 경로로 돌려보낸다.
그리고 **백엔드를 경유해 호출한다** — 프론트가 직접 부르면 내부 키가 브라우저에 노출된다.

### 언제 물을 것인가 (미정)

| | 이탈 위험 | 콘텐츠 |
| --- | --- | --- |
| A 안 받는다 | 없음 | 결과지 여덟 중 여섯만 |
| B 게임 시작 전 | 큼 | 전부 |
| C 결과 보기 직전 | 거의 없음 | 전부. 다만 사후 회상이라 이론적으로 약하다 |

**AI 쪽은 어느 쪽이든 코드가 같다.** 선언이 없는 경로가 이미 구현돼 있다.

## 3. 행동 5항목

나눗셈은 `services/inbound.to_raw_items` 한 곳에 모인다. 백엔드는 세기만 하고 분모의
정의는 AI 가 갖는다 — 공식을 바꿔도 백엔드 계약은 그대로다.

| | 항목 | 계산 | 대응 문항 |
| --- | --- | --- | --- |
| ① | `INVESTED` 투입 비중 | `(총평가액 − 현금) / 총평가액` | Q1 |
| ② | `DRAWDOWN` 손실 감내 | `abs(maxDrawdown)` · **안 오면 못 잼** | Q2 |
| ③ | `ENTRY` 진입 타이밍 | `fomoBuyCount / buyCount` | Q3 |
| ④ | `DIP` 급락 대응 | `bottomSnipeBuy / (bottomSnipeBuy + panicBottomSell)` | Q4 |
| ⑤ | `STOP` 손실 정리 | `quickStop / (quickStop + quickProfit)` | Q5 |

**백엔드에 새로 요청할 필드가 없다.** 다섯이 전부 지금 오는 시즌 payload 로 계산된다.

**②만 분모가 아니라 값 자체가 없을 수 있다.** 백엔드는 그 일차 폐장에 찍어 둔
`daily_settlements.max_drawdown` 을 보내는데, 스냅샷이 없는 일차에는 필드를 빼고 보낸다.
그때 `abs()` 를 씌우기 전에 멈춰 **못 쟀다**로 둔다 — 0 으로 접으면 "한 번도 물리지 않았다"
가 되어 이 항목이 가장 보수적인 1점으로 나간다.

**항목을 문항과 같은 순서로 둔 것은 1:1 로 계산하려는 게 아니다.** 계산은 각자 독립이고,
순서를 맞춘 것은 결과지에서 "가장 크게 갈린 항목" 의 짝을 찾기 쉬우라고다.

### 분모가 0 이면 `None` 이다. 0 이 아니다

0 으로 두면 매도가 한 건도 없는 사람이 "가장 빨리 끊었다" 로 판정된다. `None` 인 항목은
평균에서 빠지고 흐리게 표시된다.

### 알려진 한계 셋 — 측정했고, 아직 안 고쳤다

```
① 현금이 원화만 온다.   달러로 크게 들고 관망한 사람이 "전부 넣었다" 로 잡힌다.
                       totalCashKrw 를 받으면 메워진다
② 낙폭은 시장이 절반쯤 정한다.  장이 안 빠지면 낙폭도 안 난다. 다섯 중 하나로만 쓴다
③ ⑤ 의 표본이 얇다.     빠른 매도가 없는 계좌는 이 항목이 통째로 없다 (목업의 40%)
```

**⑤ 의 분모를 `sellCount` 로 두면 안 된다.** 목업 3,000계좌에서 75% 가 같은 값(0)이 되어
변별이 사라졌다. "빨리 판 것 중 손절 비중" 으로 잡아야 컷 셋이 서로 갈린다.

## 4. 판정 — 세 단계

```
① 사분위    원지표 → 1~4점        실제 분포의 P25·P50·P75 가 네 칸의 경계다
② 표본 축소  근거가 적으면 중앙으로  최종 = 2.5 + (점수 − 2.5) × n / (n + 8)
③ 합계      잴 수 있었던 항목의 평균 × 5  →  5~20  →  5단계
```

### ① 사분위 컷

```python
QUARTILES = {
    "INVESTED": ("0.2773", "0.3781", "0.4806"),
    "DRAWDOWN": ("9.3664", "15.3041", "22.1612"),   # ★ 교체 필수
    "ENTRY":    ("0.0698", "0.0922", "0.1186"),
    "DIP":      ("0.4000", "0.5263", "0.6667"),
    "STOP":     ("0.2000", "0.5000", "0.6667"),     # 뒤집어 쓴다
}
```

**임계값을 코드에 박지 않는다.** 상수로 분리해 두었고, 리허설 집계가 들어오면 한 줄로
갈아 끼운다.

```bash
uv run python scripts/build_reference.py --payload season-1-accounts.json
```

**표 밖을 더 쪼개지 않는다.** 상위 25% 안에서 얼마나 더 위인지는 컷 셋으로 알 수 없고,
외삽하면 표를 만들 때 없던 정밀도를 지어내는 일이 된다.

**`STOP` 만 뒤집는다.** 값이 클수록 손실을 빨리 끊는 것이고, 그건 Q5 의 1점이다.

### ② 표본 축소

매도 2건 중 1건이 손절이라고 "손절 성향 50%" 라 말할 근거는 약하다. 하드 컷오프 대신
연속적으로 줄이면, 거래를 거의 안 한 사람은 다섯 항목이 자연히 중앙에 모여 별도 분기 없이
"아직 알 수 없음" 에 가까운 결과가 나온다.

```
n=2 → 계수 0.20      n=20 → 0.71      n=100 → 0.93
```

**`n` 은 항목마다 다르다.** 고정하면 매도 4건으로 만든 `STOP` 점수가 전체 거래 30건을
근거로 축소를 빠져나간다.

```
n_invested = n_drawdown = buyCount + sellCount
n_entry    = buyCount
n_dip      = bottomSnipeBuy + panicBottomSell
n_stop     = quickStop + quickProfit
```

`n < 5` 이거나 원지표가 `None` 이면 흐리게(`provisional`) 표시하고 ⑥ 특징 후보에서 뺀다.

### ③ 합계는 단순 합이 아니라 평균 × 5 다

항목이 빠질 수 있어서다. 네 항목만 있는 사람의 합(4~16)을 다섯 항목 구간표(5~20)에 대면
전원이 안정형이 된다. **잴 수 있는 항목이 셋 미만이면 판정하지 않는다** — 그 사람에 대해
아는 것이 너무 적다.

### 판정할 수 없을 때

```
🌫️ 아직 그리는 중 — "아직 성향이 드러나기에는 거래가 많지 않았습니다"
```

**빈 화면을 주지 않는다.** 카드와 문장은 나가고 단계만 비운다. `investorType` 은
`UNDETERMINED` 로 나간다 — 백엔드가 이 값이 빈 문구를 저장하지 않고 버리기 때문이다.

## 5. 대조

```
같은 단계        SAME   "거의 그대로였습니다"
1단계 차이       NEAR   "조금 달랐습니다"
2단계 이상 차이   FAR    "예상과 많이 달랐습니다"
```

**"같은 단계" 만으로는 정보가 안 된다.** 두 척도가 다섯 항목을 합산하는 같은 구조라 분포
모양이 비슷하고, 그래서 우연 일치가 32% 다. 3명 중 1명은 의미 없이 "맞히셨습니다" 를 받는다.

### 두 척도의 분포 모양이 같아야 한다

행동 쪽 점수를 백분위로 5등분하면 20% 씩 고르게 나오지만, 그러면 온보딩 쪽(중립 44%)과
모양이 어긋나 **아무 관계가 없어도 불일치가 구조적으로 생긴다.**

```
모양이 같을 때   우연 일치 약 32%
모양이 다를 때   우연 일치 약 20%   ← 줄어든 12%가 가짜 불일치
```

그래서 행동 쪽도 "항목마다 1~4점, 다섯 개 합산" 으로 맞춘다.

### 가장 크게 갈린 항목

종합 단계만 비교하면 "3단계라 하셨는데 4단계였습니다" 로 끝나 **왜 그런지에 대한 답이
없다.** 항목별 점수를 양쪽 다 갖고 있으면 근거 문장이 나온다.

흐린 항목은 후보에서 뺀다 — 근거가 얇은 자리를 "가장 크게 갈렸다" 고 짚으면 안 된다.

## 6. 결과지 여덟 덩이

| # | 덩이 | 만드는 주체 |
| --- | --- | --- |
| ① | 유형 카드 (이모지·페르소나·단계) | `investor_type` 블록 |
| ② | 한 줄 | 같은 블록 |
| ③ | 내가 생각한 나 | `selfAnswers` → 템플릿 |
| ④ | 실제 모습 | **LLM** (실패하면 `actual_fallback` 블록) |
| ⑤ | 항목 막대 5개 + 대조 | 코드 |
| ⑥ | 투자 특징 3개 | `trait_title` 블록 + 본문 템플릿 |
| ⑦ | 예상과 실제의 차이 | 템플릿 |
| ⑧ | 앞으로 | `next_step` 블록 |

### ③ 은 가장 뚜렷하게 고른 둘만 싣는다

다섯을 다 이으면 읽기 어렵고, 나머지는 ⑤ 막대에 선언 점수로 이미 나가 있다.

**연결형과 종결형을 쌍으로 둔다.** 종결형에서 어미만 잘라 붙이면 "현금을 넉넉히 남기겠고"
같은 비문이 나온다.

### ⑥ 제목은 비교형으로 쓴다

점수가 사분위 **상대 위치**라 절대 주장을 하면 어긋난다. 실제로 겪었다 — 현금을 54.2%
남긴 계좌에 "현금을 남기지 않았습니다 / 현금은 54.2%를 남기셨습니다" 가 함께 나갔다.

```
금지   현금을 남기지 않았습니다
권장   현금을 덜 남긴 쪽이었습니다
```

### ⑦ 은 LLM 이 만들지 않는다

실호출에서 모델이 세 번 다 틀렸다 — 항목을 섞고, 틀을 섞고, 선언 쪽을 빠뜨렸다.
조합이 스무 가지뿐(항목 5 · 선언 방향 2 · 관찰 방향 2)이라 템플릿이 정확히 덮는다.
④ 는 두드러진 항목 둘을 잇는 일이라 조합이 폭발하고 실호출 100건 중 99건이 깨끗했다.

**LLM 이 값을 하는 자리와 못 하는 자리가 여기서 갈렸다.**

### ⑧ 의 방향은 관찰 점수에서 온다

선언에서 가져오면 현금을 잔뜩 남긴 사람에게 "덜 실어 보세요" 를 말하게 된다. 4축 시절에
실제로 겪은 결함이고(목업의 43~55%), 지금은 회귀 테스트로 고정돼 있다.

### 블록에 숫자를 쓰지 않는다

수치는 코드가 템플릿으로 넣는다. ⑥ 본문은 **반드시 payload 값을 인용**하고 지어낸 숫자가
없어야 한다. ⑦ 은 반대로 숫자를 쓰지 않는다 — 점수는 ⑤ 에서 이미 보여줬다.

---

## 7. LLM 을 어디에 쓰는가

```
④ 결과지 서술      두드러진 항목 둘을 잇는다. 실패하면 블록
온보딩 한 줄 해석   LLM 이 없으면 존재할 수 없는 경로
```

**점수가 아니라 방향 문장을 넘긴다.** `낙폭 4점` 을 주면 모델이 4를 "작다" 로 읽을 여지가
있다. 헤드라인에서 한 번 겪은 함정이다 — `mainMistake` 를 "가장 두드러졌다" 로만 적었더니
모델이 잘한 일로 읽고 "성과를 이끌었습니다" 를 냈다.

**④ 가 고르는 항목 둘은 ⑥ 특징의 앞 둘과 같다.** 다르면 한 화면에서 두 가지 이야기를
하게 된다. 테스트로 고정돼 있다.

계좌 번호·종목명·체결 원본·수익률·순위·항목 점수는 넘기지 않는다 — **익명화가 지침이
아니라 구조로 지켜진다.**

### 다섯 검사

길이·종결·숫자·금지어·방향. 하나라도 걸리면 조용히 블록 문장으로 내려앉는다. 선언이 없는
계좌에는 금지어에 대조 표현(`생각과`·`예상과`·`달리`)을 더한다 — 없는 선언을 지어내는
문장을 구조로 막는다.

**AI 가 죽어도 리포트는 열린다.** 모든 생성 자리에 폴백 블록이 있다.

## 9. 신뢰도 — 확보한 것과 못 한 것

| 종류 | 현재 |
| --- | --- |
| 계산 재현성 | **확보.** 결정론적, LLM 미개입 |
| 배치 독립성 | **확보.** 고정 사분위 컷 |
| 구조 타당도 | **부분 확보.** 항목 간 최대 \|r\| = 0.39 |
| 준거·구성 타당도 | **미확보.** 비교할 외부 기준이 없다 |
| 재검사 신뢰도 | **낮다** (아래) |
| 척도의 절대 위치 | **미확보.** 컷이 목업에서 나왔다 |

### 측정 결과

```
[항목 간 상관]   최대 0.39 (ENTRY ↔ DIP, 음수)
                같은 것을 돌려 말하고 있지는 않다

[단계 분포]      seed=11  안정형 3.6 · 안정추구 24.1 · 중립 43.4 · 적극 26.5 · 공격 2.4 (%)
                seed=7   중립 58.7%   ← 컷이 seed=11 에서 나와 다른 분포는 중앙으로 몰린다
                목표는 한 단계 40% 이하

[온보딩 조합]    4^5 = 1,024 조합 전부가 5~20 안이고 다섯 단계가 다 나온다
                다만 구간 폭이 비대칭이라(5~7 은 3점, 17~20 은 4점) 공격투자형이
                안정형보다 2.7배 나온다 (56 vs 21)
```

### 참조 컷이 시드에 고착돼 있다 ★

같은 코드로 목업 시드만 바꾸면 이렇게 갈린다. 지금 상수는 `seed=11` 에서 뽑았다.

| | seed=11 | seed=7 |
| --- | --- | --- |
| 최다 단계 비중 | 43.4% | **58.7%** |

특히 `DRAWDOWN` 은 목업 시드에 따라 P50 이 `0.57 / 3.88 / 15.08` 로 26배 흔들린다 —
목업은 일차 경계 여섯 점 근사이고 실제는 매 틱(`Account.observeValuation`)이라 자릿수가
다르다. **실데이터 교체가 남은 최우선 과제다.**

### 관찰 구간은 사람을 규정하기에 짧다

문구에 반영한다 — `달랐습니다` 가 아니라 **`여기까지만 놓고 보면 이랬습니다`**.
과장하지 않는다. 평가표에도 한계를 그대로 적는다.

**날수로 적지 않는다.** 리포트가 매일 나오고 그때까지를 누적해서 보므로 `3일간` 은 첫날과
둘째 날에 거짓이다. `지금까지`·`여기까지` 로 쓰고, 숫자 검사(`text_checks.ALLOWED_NUMERALS`)
가 비어 있어 옛 문안이 되살아나면 걸린다.

## 10. 테스트

| 대상 | 검사 |
| --- | --- |
| 사분위 환산 | 컷을 넣으면 1·2·3·4 가 정확히 갈리는가. 표 밖이 양끝 한 칸인가 |
| 뒤집는 항목 | `STOP` 이 값이 클수록 1점인가 |
| 표본 축소 | n=2 → 0.2, n=100 → 0.93. 점수가 중앙을 넘어가지 않는가 |
| 합계 | 평균 × 5 인가. 네 항목만 있어도 같은 단계가 나오는가 |
| 판정 불가 | 항목 셋 미만이면 `None` 인가 |
| 구간 | 5~20 이 다섯 단계에 겹침 없이 들어가는가 |
| 온보딩 채점 | 1,024 조합 전부가 구간 안이고 다섯이 다 나오는가 |
| 형식 오류 | 길이·범위·타입이 어긋난 답안을 선언 없음으로 다루는가 |
| 대조 | 세 구간으로 갈리는가. 한쪽이 없으면 `None` 인가 |
| 가장 갈린 항목 | 흐린 항목을 짚지 않는가 |
| ③⑦ | 선언이 없으면 **함께** 빠지는가 |
| ⑥ 제목 | 절대 주장이 없는가. 제목 방향과 점수 방향이 일치하는가 (코퍼스 300계좌) |
| ⑧ 방향 | 관찰 점수와 반대를 단정하지 않는가 (코퍼스 300계좌) |
| ④ | 프롬프트가 점수가 아니라 방향 문장을 넘기는가. ⑥ 과 같은 항목을 짚는가 |
| 단계 분포 | 다섯이 다 나오는가. 한 단계가 지나치게 몰리지 않는가 — **컷이 썩었는지 잡는 그물** |
| 어댑터 | 다섯 항목이 기존 payload 로 전부 나오는가. 분모 0 이 `None` 인가 |
| 결정성 | 같은 입력에 같은 결과인가 |

### 직접 확인

```bash
scripts/check.sh                                            # 서식·린트·테스트 요약
uv run python scripts/preview_report.py --users 300 --api   # 분포를 눈으로
```

1. 다섯 단계가 **다 나오는가** — 두셋만 나오면 컷이 데이터와 안 맞는다
2. ⑥ 본문의 수치가 제목과 같은 방향인가
3. ③⑦ 이 선언 없으면 둘 다 빠지는가 — 한쪽만 나오면 버그
4. ④ 에 숫자나 기간 표현이 섞이지 않았는가
