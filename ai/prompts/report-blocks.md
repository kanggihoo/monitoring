# 복기 리포트 문구 블록 생성 프롬프트

산출물은 블록 87개다 (AI 생성 86 + 운영자 작성 1). GMS 예산 밖의 외부 AI로 만든다.
슬롯별로 한 번에 한 슬롯씩 생성한다 — 같은 슬롯 안의 변주는 톤이 같아야 한다.
결과는 `ai/data/blocks/*.json`으로 커밋하고, 사용 모델·날짜·검수자를 하단 이력에 남긴다.

## 사용법

1. 아래 **공통 지침**을 복사한다.
2. 만들 슬롯의 프롬프트를 그 뒤에 이어 붙인다.
3. 한 번에 한 슬롯만 생성한다.
4. 생성 후 **체크리스트**로 검수한다.

---

## 공통 지침 (모든 슬롯 앞에 붙인다)

```
당신은 모의투자 게임의 복기 리포트에 들어갈 문구를 쓰는 카피라이터다.

[서비스]
2020~2026년 실제 시장을 3일 만에 재생하는 멀티유저 모의투자 게임이다.
플레이어는 30초 남짓마다 하루씩 흐르는 시장에서 28종을 사고팔고,
하루가 끝나면 자기 매매를 돌아보는 복기 리포트를 받는다.

[이 문구가 쓰이는 방식]
문구는 조건별로 미리 만들어두고, 런타임에 플레이어의 지표에 맞는 것을 골라
숫자만 채워 넣는다. 따라서 특정 개인을 가정하지 말고,
같은 조건의 누구에게나 들어맞는 문장이어야 한다.

[톤]
- 담백하게 관찰한다. 훈계하지 않는다.
- 판단을 내리지 말고 일어난 일을 서술한다.
- 약간의 위트는 좋지만 비꼬지 않는다.
- 손실을 본 사람에게 잔인하지 않되, 억지로 위로하지도 않는다.
- 문어체 종결('~습니다')을 쓴다.

[절대 금지]
1. 투자 권유·조언 — "사세요", "추천합니다", "~하는 게 좋습니다"
2. 단정적 예측 — "오를 것입니다", "떨어집니다"
3. 미래 누설 — "이후 급등하는", "훗날 10배가 되는"
   (플레이어는 다음 시세를 모르는 상태다. 결말을 아는 서술은 게임을 깨뜨린다)
4. 훈계 — "~하셔야 합니다", "명심하세요"
5. 특정 종목에 대한 가치 판단 — "좋은 종목", "위험한 종목"
6. 실제 고유명사 — 종목명·지수명·시장 사건명
   (게임의 종목은 실제와 다른 임의의 이름을 쓴다. "나스닥", "코로나 폭락",
    "금리 인상기" 같은 표현이 들어가면 익명화가 무너진다.
    종목명은 코드가 DB에서 채우므로 블록에는 어떤 이름도 넣지 않는다)
7. 기간을 날수로 적기 — "3일간", "사흘", "이번 3일"
   (리포트는 하루가 끝날 때마다 나오고 그때까지의 거래를 누적해서 본다.
    첫날과 둘째 날에는 거짓이 된다. "지금까지"·"여기까지" 로 쓴다)
8. "다음 시즌" 으로 조언 열기
   (마지막 날에만 맞는 말이다. "앞으로는" 으로 쓴다)

[출력 형식]
설명 없이 JSON 배열만 출력한다. 각 원소는 다음 형태다.
{ "id": "<슬롯코드>_<조건>_<번호>", "slot": "<슬롯>", "when": {...}, "text": "..." }
```

## 슬롯 1 — 일일 헤드라인 (36개)

리포트 최상단 한 줄. 그날 매매의 성격을 요약한다.

```
[슬롯] daily_headline
[개수] 36개 = vsIndex 3 × mainMistake 4 × 변주 3

[조건 축]
vsIndex — 내 수익률과 지수 수익률의 관계
  ABOVE   지수보다 잘했다
  SIMILAR 지수와 비슷했다
  BELOW   지수보다 못했다

mainMistake — 그날 가장 두드러진 매매 패턴
  PEAK_BUY     고점에서 샀다 (매수 후 당일 -10% 이상)
  BOTTOM_SELL  저점에서 팔았다 (매도 후 당일 +10% 이상)
  OVERTRADE    지나치게 자주 거래했다
  QUIET        거의 거래하지 않았다

[분량] 한 문장, 30자 이내
[요건]
- 숫자를 넣지 않는다. 지표는 헤드라인 아래 따로 표시된다.
- 조건 조합의 성격이 드러나야 한다.
  예를 들어 BELOW + PEAK_BUY는 "시장이 아니라 내 선택이 문제였던 날"이고,
  ABOVE + QUIET은 "가만히 있어서 이긴 날"이다.
- 같은 조건의 변주 3개는 서로 다른 각도로 접근하되 톤은 같아야 한다.

[예시]
{ "id": "HEAD_BELOW_PEAKBUY_1", "slot": "daily_headline",
  "when": { "vsIndex": "BELOW", "mainMistake": "PEAK_BUY" },
  "text": "오늘의 상대는 시장이 아니라 내 손가락이었습니다." }

{ "id": "HEAD_ABOVE_QUIET_1", "slot": "daily_headline",
  "when": { "vsIndex": "ABOVE", "mainMistake": "QUIET" },
  "text": "아무것도 하지 않은 것이 오늘의 전략이었습니다." }

위 형식으로 36개를 만든다.
```

## 슬롯 2 — 매매 별칭 (20개)

"오늘의 세 장면"에서 개별 거래에 붙는 짧은 꼬리표.

```
[슬롯] trade_alias
[개수] 20개 = tag 5 × 변주 4

[조건 축] tag — 규칙이 판정한 거래 성격
  PEAK_BUY     매수 후 당일 -10% 이상 하락
  BOTTOM_SELL  매도 후 당일 +10% 이상 상승
  BOTTOM_BUY   매수 후 당일 +10% 이상 상승
  PEAK_SELL    매도 후 당일 -10% 이상 하락 (잘 판 경우)
  NEUTRAL      위 어디에도 해당하지 않음

[분량] 명사구, 8자 이내
[요건]
- 문장이 아니라 이름표다. "<종목명> 매수 · <별칭>" 형태로 붙는다.
- 잘한 거래(BOTTOM_BUY, PEAK_SELL)와 아쉬운 거래(PEAK_BUY, BOTTOM_SELL)의
  온도 차이가 느껴져야 한다.
- NEUTRAL은 밋밋해도 된다. 오히려 튀면 안 된다.

[예시]
{ "id": "ALIAS_PEAKBUY_1", "slot": "trade_alias",
  "when": { "tag": "PEAK_BUY" }, "text": "꼭대기 수집" }
{ "id": "ALIAS_BOTTOMSELL_1", "slot": "trade_alias",
  "when": { "tag": "BOTTOM_SELL" }, "text": "바닥 세일" }
{ "id": "ALIAS_NEUTRAL_1", "slot": "trade_alias",
  "when": { "tag": "NEUTRAL" }, "text": "평범한 한 수" }

위 형식으로 20개를 만든다.
```

특수 조건 별칭은 AI로 만들지 않고 코드에서 직접 지정한다.
- `유일한 정답` — 당일 수익 거래가 1건뿐일 때
- `오늘의 유일한 실수` — 당일 손실 거래가 1건뿐일 때

## 슬롯 3 — 성향 카드 (6개)

시즌 리포트의 카드 제목과 한 줄 설명. **이름은 이미 정해져 있다** — 기획이 확정한
페르소나 다섯이라 새로 짓지 않는다. 설명·강점·주의만 쓴다.

```
[슬롯] investor_type
[개수] 6개 (5단계 + 판정 불가 1)

[단계 정의] 행동 5항목 점수를 합산해 판정한다 (`app/services/profile.py`)
  1 안정형       철벽의 자산 방어자     현금을 남기고 손실을 빨리 끊는다
  2 안정추구형    돌다리 두드리는 분석가  살펴본 자리만 담고 위험을 나눠 진다
  3 위험중립형    유연한 자산 조율사     지킬 자리와 걸 자리를 나눠 둔다
  4 적극투자형    변동성을 즐기는 트레이더 흔들리는 자리에서 기회를 찾는다
  5 공격투자형    한 방을 노리는 승부사   현금을 남기지 않고 큰 등락을 감수한다
  판정 불가      아직 그리는 중         거래가 적어 성향이 드러나지 않았다

[분량] 설명 두 문장, 각 40자 이내
[요건]
- 설명은 그 사람이 "무엇을 하는지"를 서술한다.
  잘한다/못한다는 판단은 넣지 않는다. 성과 평가는 슬롯 4가 맡는다.
- **비교형으로 쓴다.** 점수가 사분위 상대 위치라 절대 주장("현금을 남기지 않았습니다")을
  하면, 현금을 절반 넘게 남긴 계좌에도 그 문장이 나가 본문 수치와 어긋난다.
- 어느 단계도 비하하지 않는다. 1단계가 소심한 것이 아니고 5단계가 무모한 것이 아니다.

[예시]
{ "id": "LEVEL_3", "slot": "investor_type",
  "when": { "profileLevel": 3 },
  "emoji": "⚖️", "name": "유연한 자산 조율사",
  "oneLine": "한쪽으로 치우치지 않고 상황에 맞춰 옮겨 담습니다",
  "text": "지킬 자리와 걸 자리를 나눠 둡니다. 과열되면 덜어냅니다.",
  "strength": "어느 장에서도 크게 흔들리지 않습니다",
  "caution": "뚜렷한 색이 덜 드러납니다" }

위 형식으로 6개를 만든다. emoji·name·oneLine·strength·caution 을 함께 출력한다.
```

## 슬롯 4 — 작동·역작동 (15개)

"이번 장에서 통했는가"의 본문. 숫자가 들어가는 유일한 슬롯이다.

```
[슬롯] type_effect
[개수] 15개 = axis 2 (WORKED 6 · BACKFIRED 9)

[조건 축]
axis — 이것 하나뿐이다. 성향 단계로 쪼개지 않는다 (아래 마지막 줄)
  WORKED     그 습관이 이번 시즌에 유리하게 작동했다
  BACKFIRED  그 습관이 불리하게 작동했다

[분량] 한 문장, 60자 이내
[요건]
- 플레이스홀더를 반드시 포함한다. 아래 변수만 쓸 수 있다.
    {count}      판정된 유형을 만든 조건의 거래 횟수
    {winCount}   시즌에 이익으로 끝난 매도 횟수
    {returnRate} 최종 수익률 (예: +38.2%)
    {rankRate}   최종 순위의 백분위 (예: 상위 12%)
- {count}와 {winCount}는 분모가 다르다. "{count}회 중 {winCount}회" 처럼
  포함 관계로 쓰지 않는다.
- {rankRate}를 쓰는 블록에는 "requires": ["rankRate"] 를 함께 넣는다.
  순위를 모르는 계좌에서 그 블록이 후보에서 빠진다.
- 인과를 단정하지 않는다. "그래서 이겼습니다"가 아니라
  "이렇게 작동했습니다"로 서술한다.
- 앞뒤에 다른 블록이 붙으므로 접속사로 시작하지 않는다.

[예시]
{ "id": "EFFECT_WORKED_1", "slot": "type_effect",
  "when": { "axis": "WORKED" },
  "text": "{winCount}번의 수익 매도가 {returnRate}를 만들었습니다." }

{ "id": "EFFECT_BACKFIRED_2", "slot": "type_effect",
  "when": { "axis": "BACKFIRED" }, "requires": ["rankRate"],
  "text": "들어간 자리가 회복되지 않아 {rankRate}에 머물렀습니다." }

**유형에 묶지 않는다.** 성향 단계는 카드(슬롯 3)와 특징이 말하고, 이 슬롯은 "이번 장에서
통했나" 만 본다. 유형별로 쪼개면 단계가 바뀔 때마다 이 파일을 다시 써야 한다.
```

## 슬롯 5 — 장 국면 문장 (9개)

총평을 여는 연결 문장이다. **그 구간의 지수 방향으로 갈린다** (`marketMove`).

```
[슬롯] season_context
[개수] 9개 = marketMove 3 (UP · FLAT · DOWN) × 변주 3

[조건 축]
marketMove
  UP    지수가 기준(±5%)보다 올랐다
  FLAT  그 사이였다
  DOWN  기준보다 내렸다

[분량] 한 어절~두 어절. 뒤에 슬롯 4가 이어지므로 **연결 어미로 끝낸다** ("~구간이라")
[요건]
- 지수가 어떻게 움직였는지만 말한다. 사용자의 성과를 말하지 않는다 (그것은 슬롯 4 몫이다)
- 실제 사건명을 쓰지 않는다. 시장의 모양만 말한다
  "코로나 폭락 직후라" (X) → "지수가 크게 밀린 구간이라" (O)
- "시즌" 이라고 쓰지 않는다. 리포트가 매일 나오므로 마지막 날에만 맞는 말이 된다
- 슬롯 4의 첫 두 어절과 겹치지 않는다 (겹치면 "지수가 지수가" 처럼 읽힌다)

[예시]
{ "id": "CTX_DOWN_1", "slot": "season_context",
  "when": { "marketMove": "DOWN" }, "text": "지수가 크게 밀린 구간이라" }
```

**지수 값이 안 오면 폴백이다.** 시즌 엔드포인트(통합 전 경로)에는 지수가 없어서
`CTX_FALLBACK`("지금 지나온 구간에서")이 나간다 — 방향을 말하지 않는 문장이어야 한다.

## 조건 가드 (모든 슬롯 공통)

생성 후 코드에서 넣는다. AI가 만들지 않는다.

- 각 블록에 최소 조건(`minCount` 등)을 달고, 미달이면 다음 후보로 넘어간다.
- 슬롯마다 조건 없이 통과하는 기본 블록을 하나 둔다. 조건이 안 맞는 플레이어에게 빈 리포트가 나가는 것을 막는다.
- 직전 리포트에서 쓴 블록 ID를 기억해 같은 변주가 연속되지 않게 한다.

## 생성 후 체크리스트

노션 `AI 기능 정의` 7절의 검증 절차와 대응한다.

- [ ] 금지 표현 6종이 하나도 없는가 (투자 권유·단정적 예측·미래 누설·훈계·종목 가치 판단·실제 고유명사)
- [ ] 투자 권유·단정적 예측 검사를 릴리스 게이트로 돌렸는가. 하나라도 걸리면 배포하지 않는다
- [ ] 플레이스홀더가 정의된 4개 변수만 쓰는가
- [ ] 분량 상한을 지키는가 (헤드라인 30자 / 별칭 8자 / 유형 설명 40자 / 작동 60자)
- [ ] `when` 조건의 enum 값이 판정 로직과 철자까지 일치하는가
- [ ] 같은 슬롯 안 변주들의 톤이 일관되는가
- [ ] 접속사로 시작하는 블록이 없는가 (조합이 바뀌면 어색해진다)
- [ ] 조합 전수 시뮬레이션을 통과하는가
- [ ] 경계 케이스에서 문장이 깨지지 않는가 (무거래·거래 1건·분모 0·극단값)
